# 벽바둑 II · 온라인 대국실

두 사람이 서로 다른 기기에서 한 방에 접속해 즐기는 한국어 팬 제작 게임이다. 방송 자료에서 직접 확인한 규칙과 임시 배치의 근거는 RULES.md, 실행한 검사는 QA.md에 있다.

## 처음 한 번만 배포하기

1. 이 ZIP을 풀고 GitHub에서 본인의 besoyung 계정으로 로그인한다. 오른쪽 위 + → New repository에서 이름을 wallbaduk-2-online으로 지정하고 생성한다.
2. 새 저장소의 uploading an existing file을 열거나 Add file → Upload files를 선택한다. 압축을 푼 폴더 **안의 파일과 public, tests 폴더**를 함께 올리고 Commit changes를 누른다. 저장소 첫 화면에 package.json, package-lock.json, render.yaml, server.js가 바로 보여야 한다.
3. Render 대시보드에 로그인하여 New → Web Service → Git Provider에서 위 저장소를 연결한다. 처음이면 GitHub 연결 권한을 이 저장소에만 부여할 수 있다.
4. Runtime은 Node, Root Directory는 비워 둔다. Build Command는 `npm ci`, Start Command는 `npm start`, Instance Type은 Free를 선택한다. 환경변수를 직접 등록할 필요는 없다. 같은 설정이 render.yaml에도 들어 있다.
5. Deploy Web Service를 누른 뒤 Live가 되면 서비스 상단의 HTTPS 주소를 연다. 처음 접속하거나 무료 인스턴스가 절전에서 깨어나면 기다릴 수 있다.

## 두 사람이 플레이하기

1. 첫 사람은 사이트에서 닉네임을 적고 **대국실 만들기**를 누른다. 타이머는 기본 꺼짐이다. 대국 설정에서 켜거나 원형 말의 임시 시작 좌표를 바꿀 수 있다. 기본값은 빨강 B2·F6, 파랑 F2·B6이다. 왼쪽 위가 A1이다.
2. **초대 링크 복사**를 눌러 상대에게 보낸다. 상대는 링크를 열고, 처음이면 닉네임을 적어 입장한다. 닉네임이 저장된 브라우저는 자동으로 입장한다. 링크 대신 메인 화면에서 방 코드로 들어갈 수도 있다.
3. 빨강·파랑·파랑·빨강 순으로 사각 말을 하나씩 놓는다. 각자 원형 2개와 사각 2개가 되면 빨강이 먼저 움직인다.
4. 자기 말 → 표시된 목적지 → 도착 칸 테두리의 밝은 벽 후보 순으로 누른다. 집 수는 단독으로 확보한 칸만 표시한다. 양쪽 말이 모두 분리되면 점수와 승패가 확정된다. 두 사람 모두 재대결을 누르면 같은 방에서 다시 시작한다.
5. 화면이 끊기면 같은 브라우저에서 같은 초대 링크를 연다. 이동까지 한 상태라면 벽 선택부터 이어진다. 새 브라우저·시크릿 창·쿠키 삭제 후에는 기존 자리를 복구할 수 없다.

## 운영 정책

방을 만든 사람이 빨강·선공이다. 타이머는 본게임에서만 작동하고, 말 이동 뒤에도 같은 턴의 남은 시간을 사용한다. 연결이 끊겨도 타이머는 계속 간다. 만료 시 이동 전이면 합법적인 말·목적지와 벽을 서버가 무작위로 선택하고, 이동 후면 벽만 선택한다. 한쪽이 전혀 못 움직이면 자동 패스, 양쪽 모두 막히면 현재 확정 점수로 종료한다. 동점이면 가장 넓은 단독 영역, 그것도 같으면 무승부다. 이 예외 처리와 기본 좌표는 앱 운영 규칙이다.

방은 단일 Node 프로세스 메모리에 있다. **서버 재시작·재배포·무료 인스턴스 절전 시 대국이 사라질 수 있다.** 오프라인 상태로 24시간 지난 방은 정리한다. 자리 쿠키는 발급 후 24시간 유효하다. 장기 보존 및 여러 서버 인스턴스 간 공유는 지원하지 않는다.

## 로컬 실행과 테스트

Node.js 20 이상에서 프로젝트 폴더를 열고 아래를 실행한다.

```sh
npm ci
npm test
npm start
```

PC에서 http://localhost:3000 을 연다. 같은 Wi-Fi의 스마트폰은 PC의 내부 IP와 3000번 포트로 접속할 수 있다(PC 방화벽 허용 필요). 서로 다른 네트워크에서는 위의 Render HTTPS 주소를 사용한다.

브라우저 회귀 검사는 서버를 실행해 둔 채 별도의 터미널에서 아래와 같이 실행한다. Python 3가 필요하다.

```sh
python -m pip install playwright
python -m playwright install chromium
python tests/browser.py
```

배포 주소로 검사하려면 TEST_URL 환경변수에 서비스 HTTPS 주소를 지정한다. CHROMIUM 환경변수로 테스트용 Chromium 실행 파일을 지정할 수 있다.

## 소스 구조

- engine.js — 단계, 말 경로, 인접 변, 연결 영역 및 승패를 판정한다.
- server.js — 방·참가 쿠키·상태 버전·턴 제한 시간을 관리한다. 같은 출처의 HTTP POST로 명령을 받고 SSE로 두 참가자에게 서버 상태를 즉시 전달한다. 서버가 각 명령의 단계·소유권·버전을 검증한다.
- public/ — 정적 한국어 UI. 49칸, 말, 벽, 클릭 영역 모두 같은 SVG 좌표계를 사용한다.
- tests/ — 규칙 단위 테스트, 실제 HTTP/SSE 통합 테스트, Playwright 브라우저 시나리오.
